# 🦉 Букля (Buklya) — почтовый бот для Telegram и ВКонтакте

Бот подключается к вашим почтовым ящикам (Яндекс, Gmail, Mail.ru, ssau.ru и любым другим с IMAP/SMTP) и:

- присылает **новые письма** в чат с указанием ящика, текстом и вложениями;
- позволяет **ответить** на письмо прямо из чата: форматирование (жирный, курсив, подчёркнутый, ссылки, а в Telegram ещё код и цитаты) переносится в HTML письма, фото, документы и голосовые прикладываются файлами; письмо можно **набирать несколькими сообщениями**;
- показывает **последние письма** списком с листанием; по нажатию письмо открывается целиком;
- умеет писать **новые письма**, «Ответить всем», добавлять копию, менять тему, отмечать письма прочитанными.

Работает в **Telegram** и во **ВКонтакте** (бот сообщества). Один человек может пользоваться обоими: мессенджеры связываются кодом, и ящики становятся общими — подключили в Telegram, читаете и отвечаете во ВКонтакте. Каждый мессенджер работает в своём контейнере; платформы подключаются через реестр, поэтому новую (например, Matrix) можно добавить без правки ядра.

## Быстрый старт (Docker)

```bash
cp .env.example .env
# 1. впишите TELEGRAM_TOKEN (от @BotFather) и/или VK_TOKEN (ключ сообщества ВКонтакте)
# 2. сгенерируйте ключ шифрования и впишите в ENCRYPTION_KEY:
docker compose run --rm vk python -m buklya.crypto
# 3. (желательно) TELEGRAM_ALLOWED_USERS=ваш_telegram_id, VK_ALLOWED_USERS=ваш_id_вконтакте
# 4. выберите, что запускать (COMPOSE_PROFILES в .env): telegram, vk или all
docker compose up -d --build
docker compose logs -f telegram vk
```

База SQLite окажется в `./data`, логи — в `./logs`.

### Какие контейнеры запускаются

Каждый мессенджер — отдельный контейнер (`buklya-telegram`, `buklya-vk`) из одного образа. Что запускать, задаётся профилем:

| Команда | Что работает |
|---|---|
| `docker compose --profile telegram up -d` | Только Telegram |
| `docker compose --profile vk up -d` | Только ВКонтакте |
| `docker compose --profile all up -d` | Telegram и ВКонтакте (два контейнера) |

Профиль можно один раз указать в `.env` — `COMPOSE_PROFILES=all` (по умолчанию в `.env.example`), и дальше запускать просто `docker compose up -d`.

Контейнеры работают с общей базой и общим `ENCRYPTION_KEY`. Каждый проверяет почту сам и доставляет письма в свой мессенджер. Прогресс хранится отдельно для каждой платформы, поэтому письмо приходит в каждый мессенджер ровно один раз — даже если один контейнер какое-то время не работал (после запуска он догонит пропущенное, до 20 писем на ящик).

Для двух контейнеров лучше подходит PostgreSQL. SQLite тоже работает (режим WAL, ожидание блокировки до 30 с), но только если оба контейнера на одной машине.

### С PostgreSQL

В `.env`:
```
DATABASE_URL=postgresql+asyncpg://buklya:buklya@postgres:5432/buklya
COMPOSE_PROFILES=all,postgres
```
Драйвер `asyncpg` уже установлен в образе. Пароль Postgres в `docker-compose.yml` поменяйте на свой.

## Запуск без Docker

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt     # Windows: .venv\Scripts\pip ...
cp .env.example .env                           # заполнить, ключ: python -m buklya.crypto
python -m buklya telegram     # только Telegram
python -m buklya vk           # только ВКонтакте
python -m buklya all          # оба в одном процессе (удобно для разработки)
python -m buklya              # боты из BOTS или все, для которых задан токен
```

Можно запустить `telegram` и `vk` в двух терминалах — это то же самое, что два контейнера.

Требуется Python 3.10+.

## Один пользователь — несколько мессенджеров

1. В одном мессенджере нажмите «🔗 Мессенджеры» (или `/link`) — бот покажет одноразовый код вида `ABCD-2345`.
2. В другом мессенджере отправьте боту `/link ABCD-2345` (или «🔗 Мессенджеры» → «🔑 Ввести код»).
3. Готово: профили объединены. Ящики, подключённые в любом из мессенджеров, видны и работают в обоих; новые письма приходят в оба; ответить можно откуда угодно.

Подробности:
- код действует `LINK_CODE_TTL_MINUTES` минут (по умолчанию 10), срабатывает один раз, в базе хранится только его HMAC;
- если один и тот же ящик был подключён в обоих мессенджерах, остаётся одна копия;
- в только что привязанный мессенджер старые письма не присылаются — только новые;
- «✂️ Отвязать этот мессенджер» на том же экране: этот мессенджер получает новый пустой профиль, ящики остаются в остальных;
- черновики писем и незавершённые диалоги у каждого мессенджера свои;
- если пользователь заблокировал бота в одном мессенджере, письма продолжают приходить в остальные; доставка туда возобновится, когда он снова напишет боту.

## Настройка сообщества ВКонтакте

1. **Управление → Сообщения**: включите сообщения сообщества.
2. **Сообщения → Настройки для бота**: включите **«Возможности ботов»** (обязательно: без них ВКонтакте не даёт отправлять кнопки — ошибка 912 «This is a chat bot feature»; бот тогда пишет без клавиатуры и предупреждает в логе) и, по желанию, кнопку «Начать».
3. **Работа с API → Ключи доступа**: создайте ключ с правами **«Управление сообществом»** (обязательно: без него ВКонтакте не выдаёт сервер Long Poll — ошибка 15 «It cannot be called with current scopes»), «Сообщения сообщества», «Документы», «Фотографии». Ключ впишите в `VK_TOKEN`. Права у существующего ключа поменять нельзя — нужно создать новый.
4. **Работа с API → Long Poll API** Букля включает сама при запуске (версия API 5.199, события «Входящее сообщение» и «Действие с сообщением»). **Callback API** не нужен: бот сам опрашивает серверы ВКонтакте, поэтому хватит обычного компьютера с интернетом — без белого IP, открытых портов и SSL.

Чем бот ВКонтакте отличается от Telegram:
- главное меню — обычная клавиатура, а кнопки под сообщениями — callback-кнопки;
- в списке последних писем письма пронумерованы в тексте, а кнопки — это их номера: во ВКонтакте под сообщением помещается не больше 10 кнопок, поэтому на странице до 7 писем;
- команды можно писать текстом: `/add`, `/last`, `/compose`, `/accounts`, `/help`, `/cancel`, а также «начать», «помощь», «отмена»;
- ВКонтакте обычно не разрешает сообществу удалять сообщения пользователя, поэтому если удалить сообщение с паролем не получилось, бот попросит удалить его вручную;
- видео из ВКонтакте к письму приложить нельзя (API не отдаёт файл) — отправьте видео документом;
- файлы скачиваются в черновик сразу, потому что ссылки ВКонтакте на вложения временные.

## Как подключить ящик

В боте: «➕ Добавить ящик» → адрес → пароль. Серверы определяются автоматически:

1. по домену (yandex.ru, gmail.com, mail.ru, …);
2. по MX-записи домена — например, если корпоративная почта обслуживается Яндекс 360 или Google Workspace;
3. иначе пробуются `imap.<домен>` / `smtp.<домен>`;
4. если не получилось — бот предложит ввести логин или серверы вручную (`host:port`, `host:587:starttls`).

| Почта | Что нужно |
|---|---|
| Яндекс | Пароль приложения: id.yandex.ru → Безопасность → Пароли приложений; в настройках Почты включить IMAP |
| Gmail | Пароль приложения (нужна двухэтапная аутентификация): myaccount.google.com → Безопасность |
| Mail.ru | Пароль для внешнего приложения: Настройки → Безопасность |
| ssau.ru | Корпоративный логин/пароль. Серверы по умолчанию — `mail.ssau.ru`; если не подойдут, бот попросит ввести их вручную. Можно один раз поправить в `providers.yaml` |

Список провайдеров и их серверы лежат в `providers.yaml` — его можно дополнять без правки кода.

## Тексты и локализация

Все сообщения и подписи кнопок обоих ботов лежат в одном файле **`locales/ru.yaml`**. Чтобы поменять формулировку, отредактируйте файл и перезапустите бота (в Docker — пересоберите образ или смонтируйте `locales/` томом).

- Ключи вложенные: `accounts.added`, `compose.btn_send` и т.д.; `{name}` — подстановки из кода.
- Разметка — простой HTML (`<b>`, `<i>`, `<u>`, `<code>`, `<a href>`). Telegram показывает его как есть, ВКонтакте переводит в своё форматирование (жирный, курсив, подчёркнутый, ссылки).
- Если для платформы текст должен отличаться, положите ключ с тем же именем в секцию `telegram:` или `vk:` в конце файла — например, у ВКонтакте своя справка.
- Другой язык: скопируйте файл в `locales/en.yaml`, переведите и задайте `LOCALE=en`. Строки, которых нет в переводе, берутся из `ru.yaml`.

Тест `tests/test_i18n.py` проверяет, что каждый ключ, который используется в коде, есть в `ru.yaml`.

## Безопасность хранения

- Логины, пароли, адреса ящиков, серверы и метаданные писем хранятся в БД **только в зашифрованном виде** (Fernet: AES + HMAC).
- Мастер-ключ (`ENCRYPTION_KEY`) хранится только в окружении, в БД его нет. **Украденная база без ключа бесполезна.**
- Для каждого пользователя Букли из мастер-ключа выводится свой ключ (HKDF), поэтому запись одного пользователя нельзя расшифровать «от имени» другого. При связке мессенджеров данные присоединяемого профиля перешифровываются ключом основного.
- ID аккаунтов в мессенджерах (`identities`) хранятся открыто — по ним бот находит пользователя и отправляет письма; логинов и паролей там нет.
- Дубликаты ящиков ищутся по «слепому индексу» (HMAC), не раскрывающему адрес.
- Сообщение с паролем бот удаляет из чата сразу после получения (во ВКонтакте — если сообщество это разрешает).
- В лог не пишется текст сообщений пользователя — только действия (команды, кнопки).
- Ротация ключа: новый ключ в `ENCRYPTION_KEY`, старый — в `OLD_ENCRYPTION_KEYS`.

⚠️ Если потерять `ENCRYPTION_KEY`, подключённые ящики придётся добавить заново.

## Логирование

- Логи пишутся в консоль и в файл в папке `logs/`: `buklya-telegram_ГГГГ-ММ-ДД_ЧЧ-ММ-СС.log`, `buklya-vk_….log` (в одном процессе — `buklya-telegram-vk_….log`). У каждого контейнера свои файлы, даже при общей папке логов.
- Столбцы ровные: `время | уровень | источник | сообщение`. Длинные имена источников сокращаются по пакетам (`b.t.handlers.compose`).
- В консоли лог цветной: уровни (INFO — зелёный, WARNING — жёлтый, ERROR — красный), источник — голубой. Настройка `LOG_COLOR`: `auto` (по умолчанию — цвет, если консоль его поддерживает, в том числе PyCharm и Windows Terminal), `true`, `false`. В файлы цвет не пишется. В `docker compose logs` цвета нет, пока не задано `LOG_COLOR=true`.
- **Каждый день** — новый файл (переключение в полночь).
- **Каждый перезапуск** — новый файл, даже в тот же день.
- Файлы старше `LOG_RETENTION_DAYS` удаляются автоматически.

## Настройки (`.env`)

Полный список с комментариями — в `.env.example`. Общие настройки — в `buklya/config.py`, настройки платформ — в `buklya/<платформа>/settings.py` (переменные с префиксом платформы).

| Переменная | По умолчанию | Описание |
|---|---|---|
| `COMPOSE_PROFILES` | — | Какие контейнеры запускает Docker: `telegram`, `vk`, `all` (+`postgres`) |
| `BOTS` | пусто (все с токеном) | Какие боты запускает `python -m buklya` без аргументов |
| `TELEGRAM_TOKEN` | — | Токен Telegram-бота |
| `TELEGRAM_ALLOWED_USERS` | пусто (все) | Telegram ID через запятую |
| `VK_TOKEN` | — | Ключ доступа сообщества ВКонтакте |
| `VK_GROUP_ID` | определяется по ключу | ID сообщества |
| `VK_ALLOWED_USERS` | пусто (все) | ID пользователей ВКонтакте через запятую |
| `ENCRYPTION_KEY` | — | Мастер-ключ шифрования (`python -m buklya.crypto`), один на все контейнеры |
| `DATABASE_URL` | `sqlite+aiosqlite:///data/buklya.db` | Строка подключения SQLAlchemy |
| `LINK_CODE_TTL_MINUTES` | 10 | Срок действия кода связки мессенджеров |
| `POLL_INTERVAL` | 60 | Интервал проверки почты, сек |
| `POLL_CONCURRENCY` | 5 | Одновременных подключений к почте |
| `LAST_MESSAGES_COUNT` | 10 | Писем на странице списка (во ВКонтакте — не больше 7) |
| `MAX_ATTACHMENT_SIZE` | 49 МБ | Крупнее — не пересылаются (лимит Telegram 50 МБ) |
| `ATTACH_HTML_ORIGINAL` | true | Прикладывать HTML-оригинал письма |
| `LOCALE` | ru | Язык текстов (`locales/<язык>.yaml`) |
| `LOG_LEVEL` / `LOG_DIR` / `LOG_RETENTION_DAYS` | INFO / logs / 30 | Логирование |
| `LOG_COLOR` | auto | Цвет в консоли: auto / true / false |

```
buklya/
├── __main__.py          точка входа: python -m buklya [telegram|vk|all]
├── platforms.py         реестр платформ (мессенджеров)
├── config.py            общие настройки из .env
├── i18n.py              загрузка текстов из locales/*.yaml
├── app_context.py       общие зависимости ботов (БД, почта, провайдеры)
├── logging_setup.py     логи: новый файл в день и при каждом запуске
├── crypto.py            шифрование учётных данных
├── db/                  SQLAlchemy: пользователи, мессенджеры, ящики, курсоры доставки
├── mail/                IMAP, SMTP, разбор и сборка писем, провайдеры
├── services/            почта, фоновая проверка ящиков, связка мессенджеров,
│                        общая логика мастера подключения и черновика
├── telegram/            бот Telegram (aiogram 3)
└── vk/                  бот ВКонтакте (vkbottle)
locales/ru.yaml          все тексты ботов
providers.yaml           серверы почтовых провайдеров
tests/                   тесты (pytest)
```

### Как устроены данные

- `users` — пользователь Букли (человек). От его ID выводится ключ шифрования.
- `identities` — его аккаунты в мессенджерах: платформа + ID на платформе. У одного пользователя их может быть несколько.
- `mail_accounts` — ящики пользователя, общие для всех его мессенджеров.
- `delivery_cursors` — до какого письма ящик доставлен в каждую платформу.
- `mail_messages` — ссылки на показанные письма (для кнопок «Ответить», «Прочитано»).
- `link_codes` — одноразовые коды связки (только HMAC).

Это прототип: миграций нет, таблицы создаются при запуске. После смены схемы старую базу (`data/buklya.db`) нужно удалить.

### Как добавить платформу

1. Создайте пакет `buklya/<имя>/` по образцу `buklya/vk/`:
   - `__init__.py` — `PLATFORM = "<имя>"`;
   - `settings.py` — настройки с префиксом `<ИМЯ>_` и функция `config_error()` (что не задано, иначе `None`);
   - `app.py` — `create_app(ctx)`: объект с полями `platform`, `notifier` и методами `start()`, `run()`, `close()`;
   - `notifier.py` — отправка письма пользователю по ID на платформе;
   - обработчики: пользователь находится через `repo.resolve_user("<имя>", id)`, дальше — общие сервисы (`services.wizard`, `services.drafts`, `services.linking`) и тексты `Translator("<имя>")`.
2. Добавьте строку в `PLATFORMS` в `buklya/platforms.py`.
3. Добавьте название в `platforms.<имя>` в `locales/ru.yaml` и при необходимости секцию `<имя>:` с переопределениями текстов.
4. Добавьте сервис в `docker-compose.yml` (по образцу `vk`, профили `["<имя>", "all"]`).

Ядро (база, поллер, связка мессенджеров) менять не нужно.

## Тесты

```bash
pip install -r requirements-dev.txt
pytest
```

Тесты не ходят в сеть: Telegram, ВКонтакте и почтовые серверы подменяются фейками. Проверяются шифрование, логирование, локализация, форматирование ВКонтакте, разбор и сборка писем, IMAP-клиент, репозиторий, сквозные сценарии обоих ботов и сценарии с несколькими мессенджерами: ящик из Telegram работает во ВКонтакте после связки, письмо приходит в оба, два отдельных процесса доставляют каждое письмо ровно один раз, слияние профилей перешифровывает данные и убирает дубли, отвязка и блокировка бота.

## Ограничения

- Telegram не разрешает ботам скачивать файлы больше **20 МБ**, поэтому такие вложения нельзя приложить к ответу.
- Черновики писем хранятся в памяти процесса: при перезапуске недописанный черновик теряется.
- Проверяется папка «Входящие»; письма бот не помечает прочитанными (только по кнопке «✅ Прочитано»).
- Вход через OAuth (без пароля приложения) не реализован. Для Gmail и Яндекса используйте пароли приложений.
- ВКонтакте может отклонять файлы некоторых типов (например, исполняемые) — тогда вместо вложения придёт сообщение об ошибке.
