# 🦉 Букля (Buklya) — почтовый Telegram-бот

Бот подключается к вашим почтовым ящикам (Яндекс, Gmail, Mail.ru, ssau.ru и любым другим с IMAP/SMTP) и:

- присылает **новые письма** в чат с указанием ящика, текстом и вложениями;
- позволяет **ответить** на письмо прямо из чата: форматирование Telegram (жирный, курсив, подчёркнутый, ссылки, код, цитаты) переносится в HTML письма, фото/документы/голосовые прикладываются файлами; письмо можно **набирать несколькими сообщениями**;
- показывает **последние письма** списком кнопок с листанием; по нажатию письмо открывается целиком;
- умеет писать **новые письма**, «Ответить всем», добавлять копию, менять тему, отмечать письма прочитанными.

## Быстрый старт (Docker)

```bash
cp .env.example .env
# 1. впишите BOT_TOKEN (от @BotFather)
# 2. сгенерируйте ключ шифрования и впишите в ENCRYPTION_KEY:
docker compose run --rm bot python -m buklya.crypto
# 3. (желательно) ALLOWED_USERS=ваш_telegram_id
docker compose up -d --build
docker compose logs -f bot
```

База SQLite окажется в `./data`, логи — в `./logs`.

### С PostgreSQL

В `.env`:
```
DATABASE_URL=postgresql+asyncpg://buklya:buklya@postgres:5432/buklya
```
и запуск с профилем: `docker compose --profile postgres up -d --build`.
Драйвер `asyncpg` уже установлен в образе. Пароль Postgres в `docker-compose.yml` поменяйте на свой.

## Запуск без Docker

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt     # Windows: .venv\Scripts\pip ...
cp .env.example .env                           # заполнить, ключ: python -m buklya.crypto
python -m buklya
```

Требуется Python 3.10+.

## Как подключить ящик

В боте: «➕ Добавить ящик» → адрес → пароль. Серверы определяются автоматически:

1. по домену (yandex.ru, gmail.com, mail.ru, …);
2. по MX-записи домена — например, если корпоративная почта обслуживается Яндекс 360 или Google Workspace;
3. иначе пробуются `imap.<домен>` / `smtp.<домен>`;
4. если не получилось — бот предложит ввести логин или серверы вручную (`host:port`, `host:587:starttls`).

| Почта | Что нужно |
|---|---|
| Яндекс | Пароль приложения: id.yandex.ru → Безопасность → Пароли приложений; в настройках Почты включить IMAP |
| Gmail | Пароль приложения (нужна двухэтапная аутентификация): myaccount.google.com → Безопасность |
| Mail.ru | Пароль для внешнего приложения: Настройки → Безопасность |
| ssau.ru | Корпоративный логин/пароль. Серверы по умолчанию — `mail.ssau.ru`; если не подойдут, бот попросит ввести их вручную. Можно один раз поправить в `providers.yaml` |

Список провайдеров и их серверы лежат в `providers.yaml` — его можно дополнять без правки кода.

## Безопасность хранения

- Логины, пароли, адреса ящиков, серверы и метаданные писем хранятся в БД **только в зашифрованном виде** (Fernet: AES + HMAC).
- Мастер-ключ (`ENCRYPTION_KEY`) живёт только в окружении, в БД его нет. **Украденная база без ключа бесполезна.**
- Для каждого пользователя из мастер-ключа выводится свой ключ (HKDF) — запись одного пользователя нельзя расшифровать «от имени» другого.
- Дубликаты ящиков ищутся по «слепому индексу» (HMAC), не раскрывающему адрес.
- Сообщение с паролем бот удаляет из чата сразу после получения.
- В лог не пишется текст сообщений пользователя — только действия (команды, кнопки).
- Ротация ключа: новый ключ в `ENCRYPTION_KEY`, старый — в `OLD_ENCRYPTION_KEYS`.

⚠️ Если потерять `ENCRYPTION_KEY`, подключённые ящики придётся добавить заново.

## Логирование

- Логи пишутся в консоль и в `logs/buklya_ГГГГ-ММ-ДД_ЧЧ-ММ-СС.log`.
- **Каждый день** — новый файл (переключение в полночь).
- **Каждый перезапуск** — новый файл, даже в тот же день.
- Файлы старше `LOG_RETENTION_DAYS` удаляются автоматически.

## Настройки (`.env`)

| Переменная | По умолчанию | Описание |
|---|---|---|
| `BOT_TOKEN` | — | Токен бота |
| `ENCRYPTION_KEY` | — | Мастер-ключ шифрования (`python -m buklya.crypto`) |
| `ALLOWED_USERS` | пусто (все) | Telegram ID через запятую |
| `DATABASE_URL` | `sqlite+aiosqlite:///data/buklya.db` | Строка подключения SQLAlchemy |
| `POLL_INTERVAL` | 60 | Интервал проверки почты, сек |
| `POLL_CONCURRENCY` | 5 | Одновременных подключений к почте |
| `LAST_MESSAGES_COUNT` | 10 | Писем на странице списка |
| `MAX_ATTACHMENT_SIZE` | 49 МБ | Крупнее — не пересылаются (лимит Telegram 50 МБ) |
| `ATTACH_HTML_ORIGINAL` | true | Прикладывать HTML-оригинал письма |
| `LOG_LEVEL` / `LOG_DIR` / `LOG_RETENTION_DAYS` | INFO / logs / 30 | Логирование |

## Структура проекта

```
buklya/
├── __main__.py          точка входа (python -m buklya)
├── config.py            настройки из .env
├── logging_setup.py     логи: новый файл в день и при каждом запуске
├── crypto.py            шифрование учётных данных
├── db/                  SQLAlchemy: модели, подключение, репозиторий
├── mail/                IMAP, SMTP, разбор и сборка писем, провайдеры
├── services/            асинхронный фасад почты, фоновая проверка ящиков
└── telegram/            хендлеры, клавиатуры, отображение писем, middleware
providers.yaml           серверы почтовых провайдеров
tests/                   тесты (pytest)
```

## Тесты

```bash
pip install -r requirements-dev.txt
pytest
```

Тесты не ходят в сеть: Telegram и почтовые серверы подменяются фейками. Проверяются шифрование, логирование, разбор и сборка писем, IMAP-клиент, репозиторий и сквозной сценарий бота (подключение ящика → новое письмо → ответ из нескольких сообщений с файлом → список последних писем).

## Ограничения

- Боты Telegram не могут скачивать файлы больше **20 МБ**, поэтому такие вложения нельзя приложить к ответу.
- Черновики писем хранятся в памяти процесса: при перезапуске недописанный черновик теряется.
- Проверяется папка «Входящие»; письма бот не помечает прочитанными (только по кнопке «✅ Прочитано»).
- Вход через OAuth (без пароля приложения) не реализован. Для Gmail и Яндекса используйте пароли приложений.
